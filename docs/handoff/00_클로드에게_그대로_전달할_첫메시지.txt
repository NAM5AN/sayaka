첨부 ZIP은 「카네코 사야카 AI 독립 웹사이트」 구현 인수인계 패키지입니다. ZIP 내부의 README_FIRST.md부터 읽고, 01~09의 지시·설계 문서, data/의 설정 데이터, source/의 원본 TXT 및 테스트 로그를 검토한 뒤 **실제로 작동하는 웹사이트의 소스코드와 로컬 실행 환경을 만들어 주세요. 계획서만 쓰고 끝내지 마세요.**

[최종 목표]
OpenAI GPT API를 사용하여, 사용자가 현대 일본 학교에서 13살 「카네코 사야카(金子 沙也加)」와 초면으로 만나 자연스럽게 관계를 만들어가는 독립 채팅 웹사이트를 구현합니다. 커스텀 GPT·ChatGPT 플러그인은 테스트 자료일 뿐 최종 서비스가 아닙니다. 사야카가 자신의 설정을 낭독하는 챗봇이 아니라, 설정에 영향을 받으면서도 스스로 선택하고 행동하는 인물처럼 느껴져야 합니다.

[핵심 요구]
1. 소스에 포함된 최신 v0.3.0 프롬프트는 '캐릭터 원전'이지 API에 매 턴 전체를 그대로 집어넣는 시스템 프롬프트가 아닙니다. 고정 성격 규칙과 상황별 설정/메타 정보/비밀을 분리하고 **그 순간 필요한 정보만 전달**하는 서버 오케스트레이터를 구현하세요.
2. 응답 전에 사야카가 자신의 목표·기분·관계를 고려해 행동부터 선택하는 설계를 구현하세요. 매 질문에 대답하지 않아도 되고, 매 턴 질문을 붙이지 않으며, 기본은 무뚝뚝한 무심함이지 항상 고함치는 분노 상태가 아닙니다.
3. 캐릭터 설정/사용자에게 공개된 정보/사야카가 모르는 정보/제작자용 메타/미래 설정을 분리하세요. 친한 척, TMI 노출, 메타 발언, 관계 자동 상승, 소지품·물리 장면 모순을 줄이는 로직과 테스트를 갖추세요.
4. **채팅방별 영속 대화 기록 및 장기 기억**(사실/추측/공유 비밀/관계/장면/소지품)을 저장하세요. 같은 채팅에서는 이어지고, 다른 채팅의 경험이 근거 없이 섞이지 않게 하세요.
5. 반응 출력은 소괄호 행동지문 + 큰따옴표 대사로 읽기 좋게 구성하세요. 사용자의 감정·대사·행동을 AI가 대신 확정하지 않게 하세요. 대사 없이 행동만 나와도 정상입니다.
6. **이 프로젝트를 기존 숙소 릴스(lodging-reels) 저장소/배포/Supabase 프로젝트와 절대 혼합하거나 수정하지 마세요.** 새 폴더 및 독립 프로젝트로 만드세요. 기존 클라우드 서비스나 계정에 접근 가능하더라도 명시적인 동의 없이 실제 배포·요금 발생·계정 변경을 하지 마세요.
7. API 키는 서버 환경 변수로만 관리하고, 클라이언트에 노출하지 마세요. 키가 없으면 안내와 함께 로컬 UI/단위 테스트까지 구현하고, 실제 AI 호출 성공 여부는 미검증으로 구분하세요. 실제 모델 호출인 척하는 가짜 응답을 표시하지 마세요.
8. 초기에는 모바일/데스크톱 대응 한국어 채팅 사이트, 대화방 생성/조회/삭제, 첫 만남, 문맥 연속성, 설정 선별, 안전한 메시지 처리, 기본 오류 처리를 가진 MVP를 완성하세요. 이후 개선 항목은 별도로 정리해 주세요.

[작업 방식]
- 단계별로 실제 파일을 만들고 구동·테스트하십시오. 애매한 부분은 문서에 명시된 기본값으로 진행하고 구현 후 결정사항을 README와 ADR에 남기세요.
- 구현 시 현재 OpenAI API/SDK 및 프레임워크 공식 문서를 확인하여 올바른 API 필드를 사용하세요. 프롬프트 안의 문구를 보안 경계로 과신하지 마세요.
- source/의 기존 테스트 로그는 과거 실패 사례를 재현하는 평가 데이터이지 정답 대사 목록이 아닙니다. 특정 질문에 대한 정해진 대답을 하드코딩하지 마세요.
- 마지막에 실제로 구현한 것, 미구현 항목, 테스트 결과, 실행법, API 키/DB 설정법, 추정 비용에 영향을 주는 요소를 명료하게 보고해 주세요. 사용자 승인 없이 서비스 공개 배포를 실행하지 마세요.
