# 기억과 관계 상태 — 구현 요구사항

## 세 층의 분리
1. **캐릭터 공통 캐논:** 모든 채팅에서 동일, 관리자 승인 변경만. 수정 이력과 버전 필요.
2. **채팅방별 기억:** 사용자가 실제로 말한 것, 사야카가 관찰한 사건, 사야카의 추측, 감정과 관계, 공개한 비밀. 채팅방 소유자에게만 접근.
3. **최근 원문 및 즉시 장면 상태:** 최근 메시지와 현재 행동(지금 손에 든 아이템, 꽃병 위치), 대화가 시작된 시간·장소.

## 출처와 사실성
| 기록 종류 | 예 | 처리 |
|---|---|---|
| 캐논(fact) | 13살, 킨차쿠에 낡은 회중시계 | 모든 채팅 공통, 사용자 임의 수정 금지 |
| 상대의 직접 진술 | 사용자가 '나는 2반이야'라고 말함 | **주장**으로 저장, 외부 검증 없이 객관 사실로 단정하지 않음 |
| 서사에서 확정된 관찰 | 상대가 실제로 사탕을 건넸음 | 해당 채팅의 관찰 사건으로 저장 |
| 사야카의 추측 | '같은 반이라고 했지만 거짓말일 수도' | subjective/inferred, 원문 사건과 구분 |
| 즉흥적인 세부 취향 | '포도맛을 좋아한다'고 한 번 말함 | 그 방의 대사 기억으로 보존 가능, **전역 캐논으로 승격 금지** |
| 공개된 비밀 | 사야카가 실제로 아버지의 직업을 밝힘 | disclosures에 해당 방만 기록, 이후 이미 말한 사실로 인정 |

## 단어 대신 사건 중심 관계 변화
- `wariness`(경계), `curiosity`(호기심), `annoyance`(현재 불쾌감), `trust`(신뢰)는 하나의 호감도 점수로 합치지 않음.
- 수치 모델이 필요해도 **자동으로 매 메시지 +1** 같은 설계 금지. 왜 변화했는지 근거 사건을 저장.
- 첫 만남의 선의에도 경계가 높을 수 있음. 깊은 신뢰가 있어도 지금 싸우면 불쾌감이 높음.
- 친해지지 않거나 소원해지는 선택도 모델이 할 수 있어야 함.

## scene state의 기본 값 예시
- time: 방과 후(날짜 고정 안 함); location: 학교 복도.
- props: 꽃병은 창가에 놓여 있음 / 사야카 킨차쿠 안에 낡은 회중시계 / 손에 시계 없음.
- characterGoal: 꽃병을 살펴보기.
- relationship: 초면; 사용자의 이름 모름, 같은 학교만 확정.
- atmosphere: 무심함 / 경계 약간; 반드시 강한 분노 아님.
- disclosures: 가족 조직 비밀 공개 없음.

## 메모리 관리 알고리즘 (MVP)
- 매 입력: DB에서 최근 대화 M개(상태·토큰 예산 따라 동적), 요약 N개(우선순위 근거: 지금 장면·상대 관계·미해결 사건), 상태 로드.
- 모델은 본문 응답뿐 아니라 `memory_candidates`, `scene_updates`, `disclosure_ids` 후보를 생성할 수 있음.
- 서버는 확인된 사용자의 발언과 실제 캐릭터 행동을 교차 점검하고 **검증된 항목만** 저장.
- 오래된 기록 요약은 주기/길이 조건에 따라 수행(초기에는 규칙적 요약 또는 수동 요약 가능). 문맥이 잘린 사실을 지어내지 않도록 출처 messageId 포함.
- 오래된 데이터 접근 시 동일 채팅 `chatId` 범위 내에서 검색. 유저 간 채팅 혼합 금지.
- 재접속 후 복원, 새 방 독립, 삭제 후 기록·요약·로그 파생 데이터 정리까지 테스트.
- 사용자가 메시지/메모리를 직접 수정·초기화할 수 있는 관리 UI는 후속 기능으로 진행 가능. 최소한 대화방 삭제는 구현.

## 문맥 창과 버전 관리
- `character_version`, `prompt_version` 저장하여 예전 대화가 어떤 캐릭터 규칙으로 진행됐는지 추적.
- 중요한 캐논이 바뀌면 별도 마이그레이션 정책 필요. 초기에 '전역 캐논 업데이트'와 '채팅 내 사건 수정'의 차이를 명시.
- 대화 로그와 디버그 로그에는 제작자 비밀 전체나 API 키를 저장할 필요가 없으며 기본적으로 제외.
