# 웹 UI/UX 가이드 — 사야카와 대화하는 경험

## 제품 경험
- **카네코 사야카와 실제 학교에서 마주친 듯한 몰입감.** 복잡한 게임 UI가 아니라 자연스러운 채팅 인터페이스.
- 모바일과 데스크톱 대응. 긴 대화도 가독성 확보. 특별한 이미지 소스가 없는 상태이므로 **공식 초상/일러스트 자산을 임의로 만들어 기존 그림이라고 주장하지 말 것**. 기본은 타이포그래피·꽃 문양의 절제된 UI 사용.
- 웹 인터페이스는 한국어. 사야카 대사/행동은 소괄호 지문 + 큰따옴표 대사 유지; 내부 상태나 호감 점수를 일반 화면에 노출하지 않음.

## MVP 화면
1. **사이드바/방 목록** — 새 대화, 최근 방, 방 삭제(확인), 현재 방 선택. 모바일에서는 오버레이 또는 드로어.
2. **대화 화면** — 시작 장면, 사용자 메시지, 사야카의 대사·행동지문을 시각적으로 구분(폰트/배경으로 절제), 시간 표시는 선택. 자동스크롤은 사용자가 과거를 읽을 때 튀지 않도록.
3. **입력 영역** — Enter 전송/Shift+Enter 줄바꿈; 모바일 전송 버튼; 전송 중 중복 제출 제한; 오류 시 재시도.
4. **상태 UI** — '답변 생성 중', 네트워크 오류, API 키 미설정, 장기 대화 요약 등 일반적인 상태 안내. AI 역할극 문장과 앱 시스템 상태를 섞지 않음.
5. **설정(최소)** — 서비스가 실제 API와 연결되었는지, 데이터/대화 삭제, 사용자에게 보여줄 개인정보/데이터 보존 안내. 공개 관리자 창이 없으면 더 좋음.

## 디자인 기본값 — 개발 편의를 위한 제안, 캐논 아님
- 어두운 먹색·버건디·미색 계열의 고전적인 일본 정서; **지나친 야쿠자 문양이나 붉은 피 연출은 금지**.
- 섬세한 타이포그래피와 여백 중심. 채팅 길이가 길어져도 구조가 명확해야 함.
- 명시적 사용자가 제공한 이미지 자산이 없으면 저작권이 불명확한 팬아트·애니 이미지 무단 사용 금지.
- 접근성: 충분한 대비, 키보드 이동, 포커스, aria-label, 축소 화면 확인.

## 장면 진행과 자율성
- 첫 장면 이후 AI는 사야카의 자기 행동을 자연스럽게 전개할 수 있으나 **사용자 캐릭터의 발언·표정·행동을 대신 확정하면 안 됨**.
- 대사 없는 행동만 출력되는 턴 허용, 정적 장면에서 불필요한 사건/질문 강요 금지.
- 메타/OOC 테스트는 일반 공개 채팅 인터페이스의 권한 설정으로 취급하지 않음. 관리자 점검 기능은 별도 인증된 관리자 화면이나 개발 로그로.

## 최소 디바이스 수용
- 작은 스마트폰 가로폭에서도 입력창이 잘리지 않아야 함.
- 데스크톱에서 마크다운 코드 노출/깨짐 없이 텍스트·지문 렌더링.
- 느린 모바일 네트워크에서 타임아웃·재전송 명확하게 안내.
