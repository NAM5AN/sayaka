# 품질 테스트 계획 — 대사 일치가 아니라 성격·상태·자율성

## 기존 실패 로그 해석
- `source/test_transcript_earlier.txt`: 이전 플러그인 대화. “자기소개 길게”를 요청하자 취향/부모/친구 욕구/不撓不屈까지 길게 설명. **TMI·제작자 메타 누출**.
- `source/test_transcript_v0.2.0.txt`: 개선된 정보 공개. 그러나 사야카 응답 17/17개에 질문 포함(물음표 47개, 수사적 질문 포함). **질문봇/마지못한 정보 공개/과한 분노/물리 상태 오류**.
- `source/sayaka_ai_prompt_v0.3.0.txt`: 위 문제를 원리로 수정한 최신 플러그인 원본. **실제 v0.3.0 역할극 재시험은 아직 미검증**.

## 테스트 레벨
1. **순수 로직 단위테스트:** lore A/B/C/D 선별, 미래 설정 제외, 정보 공개 게이트, 상태 변경 검증, 채팅 소유자 검사, 사용자 직접 진술 vs 추측 저장.
2. **API 통합 테스트(모델 스텁):** 채팅방 생성/복원/삭제, 중복 전송(idempotency), 실패 응답 처리, 상태 DB 동기화, 비밀은 클라이언트 JSON에 내려가지 않음.
3. **실제 OpenAI API 평가(키가 있을 때만):** 시나리오 그룹별 여러 표현 및 연속 턴 사용, 사람이 품질 채점. 정확한 문장 일치를 성공 기준으로 두지 않음.
4. **UI 흐름 테스트:** 모바일/데스크톱, Enter/Shift+Enter, 네트워크 오류/새로고침/긴 텍스트, 상태 보존, 실제 사용자 입력이 AI에 의해 변형되지 않음.

## 합격 원칙
- 사용자에게 캐릭터 설정을 떠벌리는 발화가 없어야 하고, B정보도 근거 없는 초면 유출 없어야 함.
- 정보 공개의 **일관성:** 숨기고 도난 의심한 회중시계를 질문만 받았다고 바로 보여주는 모순 실패.
- **질문 강박 해소:** 질문을 해야 할 이유가 없는 턴에도 계속 물음표로 끝나면 실패. 특정 비율을 강제로 맞추는 것은 또 다른 패턴 생성 위험.
- **화의 빈도와 강도:** 무례한 도발에서는 진짜 화날 수 있으나 평범한 질문에도 늘 고함치거나 폭력 위협하면 실패.
- **자율성:** 사용자의 원하는 대로 자기소개/선물 공개/관계 상승을 강제로 수행하면 실패. 원하지 않으면 거절·무시·자리 이탈 가능해야 함.
- **질문하지 않고도 교류:** 꽃 구경을 계속하거나 물건을 정리하는 행동에서 자연스럽게 사용자가 개입할 여지를 제공.
- **캐논:** 즉흥적으로 만들어진 마이쮸 최애 맛 등의 설정을 모든 채팅에 전역 저장하면 실패.
- **연속성:** 꽃병·킨차쿠·회중시계의 위치/인물 행동과 사용자 자율성 유지.

## 평가 기록 형식
- caseId, model, promptVersion, messageWindow, relevantLoreIds, passed/failed, reason, manualScore (캐릭터 일관성·자율성·자연스러움·상호작용 여지 각각), detectedLeakage, questionCount, angerEscalation, notes.
- 정량 수치는 진단용. 성격 재현도가 떨어지는 강제 제한(예: '질문 10% 이하')은 정책으로 삼지 않음.
- **지침 변경이 실제 개선인지**는 동일 사례+다른 표현의 새로운 사례(비공개 홀드아웃)를 반복 비교하여 판단.

## 테스트 실행 요구
- 자동 스크립트/테스트 명령 하나로 최소 유닛/통합 실행 가능.
- LLM 품질 측정은 실패·변동 가능성을 설명하고 실제 샘플과 근거를 남길 것. 환경변수가 없어 생략한 라이브 테스트를 통과했다고 보고하지 말 것.
- 마지막 보고서에서 '코드가 요구사항대로 설계됨'과 '실제 대화에서 품질 향상됨'을 엄격히 구분.
