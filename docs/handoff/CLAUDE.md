# Claude Code — 카네코 사야카 독립 웹사이트 제작 지침

**반드시** 먼저 `00_클로드에게_그대로_전달할_첫메시지.txt`와 `README_FIRST.md`를 읽고, 프로젝트 내부 설계 문서 `01_...`부터 `09_...`까지 확인하라. 소스의 `sayaka_ai_prompt_v0.3.0.txt` 및 대화 로그는 원전·검증 자료이며 API 호출에 파일 전체를 그대로 통째로 넣지 않는다.

## 구현할 결과
OpenAI GPT API로 사야카(13살, 초면인 같은 학교 학생과의 1:1 역할극)와 대화 가능한 **실제로 실행되는 독립 웹사이트**를 만든다. 반응형 대화 UI, 대화방별 영속 기록·관계 기억, 공개 정보 등급 선별, 사야카의 자율 행동 결정, 상태 검증, 자동 테스트가 MVP 핵심이다.

## 캐릭터 엔진 품질
- 퉁명스럽고 성질 나쁘지만 **상시 분노**가 아님.
- 사용자 질문에 항상 대답하지 않음. 거절을 했으면 실제로 비공개 유지.
- 매 턴 질문하지 않음. 사야카가 자기 일, 관찰, 참견, 침묵, 거리 두기를 선택할 수 있음.
- 공개 프로필 낭독/TMI/미래 설정/메타 용어 노출 금지. 필요한 상황에서만 적절하게 행동으로 보여 줌.
- 꽃병·킨차쿠·회중시계의 물리적 위치와 감정·기억의 연속성 유지. 사용자 행동을 대신 확정하지 않음.
- 자잘한 즉흥 취향/대사를 모든 채팅의 전역 캐논으로 승격하지 않음.

## 보안/작업 격리
- `lodging-reels` 저장소·프로젝트·키·배포 설정을 변경하지 말 것. 반드시 독립 폴더/저장소.
- API 키는 서버에만. 관리 권한은 채팅 OOC 텍스트가 아니라 인증으로.
- 13살 캐릭터와의 나이에 맞는 일상 중심 안전 정책을 적용.
- 키/DB가 없으면 UI·로직·테스트를 구현하고 무엇이 실서비스로 미검증인지 명시. 비용 발생 및 공개 배포는 승인 전 수행하지 말 것.

## 산출물
계획만 제출하지 말고 실제 코드, 로컬 실행법, DB 마이그레이션, `.env.example`, 유닛/통합 테스트 결과, 코드/품질의 검증과 미검증을 구분한 보고를 제출하라.

**절대 원칙:** 설정은 행동을 형성할 뿐, 대사로 줄줄이 소개하기 위한 목록이 아니다. '성격은 불친절하게, 서술은 친절하게.'
